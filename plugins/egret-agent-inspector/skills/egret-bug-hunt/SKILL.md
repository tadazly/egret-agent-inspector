# 探索式排查 Egret 游戏缺陷

目标是找出真实缺陷并给出可复现的证据，不是把流程跑完。

## 准备

1. 按 `egret-game-operation` skill 连接扩展并确认舞台就绪。
2. 与用户确认排查范围（某个面板、某条流程或整体巡检）和禁止操作（消耗道具、付费、领奖、提交不可逆数据等）。
3. 查询相关 `egret_notes`，再用 `egret_get_errors clear:true` 建立错误基线。

## 探索

未知交互每轮只做一件事；已确认的安全路线可短批量跑到检查点：

1. 用 `egret_observe` 拿动作表，直接按编号 `egret_act` 点尚未访问的入口，执行结果里就带新的动作表。目标不在表里时按明确属性用 `egret_find`、按自然语言描述用一次 `egret_locate`。定位仍有歧义时先消歧，禁止按场景顺序盲点；`occluded` 的条目先处理遮挡。
2. 用 `egret_act` 的 `{"op": "wait", "until": {...}}` 等待预期界面；带动画的面板加 `stableMs`。
3. 用 `egret_observe` 的文案行和 `egret_find` 检查界面内容，必要时 `egret_screenshot` 看整体。
4. 在检查点或状态异常时读取新增错误，不要为每句对话重复拉取。
5. 记录：入口路径、操作、观察到的结果、错误。

浏览器闪退或扩展断连时改用 `egret-session-recovery`；同一步骤再次闪退则保留指标并按崩溃缺陷报告。

覆盖顺序：主要入口 → 每个面板的标签页和列表 → 关闭与返回 → 重复打开同一面板。

## 重点检查项

- **页面报错**：未捕获异常、Promise 拒绝、`console.error`；同一错误反复出现（`count` 增长）通常是每帧报错，优先级高。
- **资源缺失**：`resource` 类型错误，或 `egret_find` 得到的 `source` 为空、显示尺寸为 0。
- **界面异常**：文本被截断（实际宽度超出容器）、组件重叠、超出舞台范围、数值为 `undefined`/`NaN`/占位文案。
- **交互无响应**：点击成功但「变化」那行说界面没变，且没有新错误 —— 用 `egret_observe` 的 `format: "json"` 看目标是不是被 `occluded`，确认点到的是不是预期对象。
- **状态残留**：关闭再打开后仍显示上一次的数据，或列表项数量持续增长。
- **继续条件**：界面仍能推进时，普通 warning 和资源告警只记录，不结束探索；当前分支阻塞后继续其他可达入口。

## 判断与报告

- 区分三类结论：真实缺陷、环境或数据问题（账号状态、配表缺失、服务未启动）、工具或定位问题。证据不足时写“疑似”，不要断言。
- 每个缺陷给出：复现步骤（定位条件写清楚）、期望与实际、错误原文、截图。
- 报告按严重程度排序，并说明本次覆盖了哪些入口、哪些没走到。
- 不修改游戏代码或数据来“绕过”问题；只有用户要求时才进一步定位到代码。
- 走通的真实入口写成 `route` 笔记；调试直达和恢复动作必须分开记录。
